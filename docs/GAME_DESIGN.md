# swITch 게임 설계 문서

swITch의 게임 규칙과 메카닉을 정의하는 문서다. 여기 나오는 수치(속도·쿨타임·사거리·시간 등)는 **플레이테스트로 조정할 초기값**이며, 최종 밸런스가 아니다. 실제 상수는 `shared` 패키지 한 곳에 모아 클라이언트·서버가 공유한다(→ `ARCHITECTURE.md` 참고). 확정되지 않은 항목은 **TBD**로 표시한다.

---

## 1. 개요

swITch는 술래잡기를 기반으로 한 실시간 멀티플레이어 io 게임이다. 한 방에 3~8명이 들어가, 한 명은 **술래(tagger)**, 나머지는 **도망자(runner)**로 시작한다. **팀전이 아닌 개인전**이다. 술래는 게임 도중 계속 바뀌며, 도망자끼리도 서로를 방해할 수 있다. 핵심 정서는 *"곰이 달려올 때, 곰보다 빠를 필요는 없다. 옆 사람보다만 빠르면 된다."*

맵은 사방에서 조여오는 **자기장**으로 점점 좁아지고, 생존자가 2명이 될 때까지 진행된다.

---

## 2. 라운드 흐름

```
로비(방)  →  게임 시작  →  인게임 진행  →  게임 종료  →  결과
 대기       카운트다운    (자기장 수축)    생존 2명      통계/보상
```

1. **로비**: 방에 모여 대기. 방장이 맵 선택, 각 플레이어는 스킬 로드아웃(슬롯2) 선택. 최소 3명이어야 시작 가능. **준비(ready) 개념은 없다** — 방장이 시작을 누르면 바로 카운트다운.
2. **게임 시작**: 방장이 시작 → **카운트다운**(갑작스러운 시작 방지 목적). 카운트다운이 시작된 순간부터 "게임이 시작된 판정" — 이후 입장자는 다음 판부터 참가(관전 가능). 카운트다운 중 이탈로 3명 미만이 되면 취소되고 로비로 복귀. 카운트다운 종료 시 스폰 위치 배치(맵별 사전계산된 `start_pos`, 인원수별 원형 배치), 초기 술래 1명 무작위 지정.
3. **인게임 진행**: 실시간 이동·스킬·추격. 시작 후 일정 시간 뒤부터 자기장 수축 시작.
4. **게임 종료**: 생존자가 2명(도망자 1 + 술래)이 되면 종료.
5. **결과**: 킬 수, switch 성공/시도 등 통계 표시 및 계정 스탯 반영.

- **관전**: 아웃된 플레이어와 게임 중 입장자는 관전한다. 관전은 **두 모드** — ① 특정 플레이어를 선택해 **그 사람의 시야로 보기**, ② **자유 시점 카메라** — 를 언제든 자유롭게 전환할 수 있다. 짧고 스피디한 게임(판당 ~5분 이내 목표)이라 관전 고스팅은 감수한다(→ `WS_PROTOCOL.md`).

---

## 3. 역할

| 역할 | 설명 | 아웃 여부 |
|---|---|---|
| **술래 (tagger)** | 도망자를 접촉해 아웃시킨다. 기본 이동속도 +10%. | 아웃되지 않음 |
| **도망자 (runner)** | 술래에게 잡히지 않고 생존한다. Switch로 술래를 떠넘길 수 있다. | 술래에게 접촉 시 아웃 |

- 술래는 항상 **정확히 1명**이다.
- 아웃되는 것은 도망자뿐이다. 술래는 아웃되지 않으므로, Switch로 술래가 되는 것은 곧 "즉각적인 아웃 위험에서 벗어나는 것"을 의미한다.

---

## 4. 승패 조건

- 생존자가 **2명**(도망자 1 + 술래) 남으면 게임 종료. 이 2명이 최종 생존자다.
- 상세 순위는 아웃된 순서(`death_order`)로 매긴다.
- **중도 이탈(탈주)은 그 시점의 아웃으로 처리**한다(`death_order` 부여, 스탯 반영). 단 로그인 유저의 일시적 접속 끊김은 10초 재접속 유예가 있다(→ `WS_PROTOCOL.md`).

## 5. 이동 & 속도 시스템

- 좌표계: 1타일 = **256px**. 플레이어는 반지름 **80px**(지름 160px)의 원.
- 시뮬레이션 틱: **60Hz**. (네트워크 전송률은 이와 별개 → `ARCHITECTURE.md`)
- 접촉 판정: 두 플레이어의 중심 거리가 **160px(반지름 합)** 미만이면 접촉.

### 속도 공식

```
속도 = 기본이동속도 × (1 + Σ증가요소) × (1 − Σ감소요소)
```

증가/감소 요소는 각 그룹 안에서 **가산 스택**된다.

| 구분 | 요소 | 값 | 지속 | 조건 |
|---|---|---|---|---|
| 증가 | 술래 기본 | +10% | 술래인 동안 | 술래 역할 |
| 증가 | 유체화(dash) | +50% | 10s | dash 사용 |
| 증가 | 광란(frenzy) | +10% | 5s | 아래 "광란" 참고 |
| 감소 | 탈진(exhaust) | −50% | 10s | exhaust에 피격 |
| 감소 | switch 피해 | −10% | 5s | switch로 술래에서 강등 |

**광란(frenzy) 발동 조건**:
- 술래가 된 직후(게임 시작 / 강제 교체 / switch로 지목당해 술래가 됨)
- switch를 **성공적으로 사용한 시전자**(도망자로 남지만 이탈 버스트를 받음)

### 초기 수치 (튜닝 대상)

| 항목 | 초기값 | 비고 |
|---|---|---|
| 기본 이동속도 | **300px/s** (60Hz 기준 5px/틱) | 30타일 맵 횡단 ≈ 26초. 템포 조절의 1순위 레버 |

> 참고: 맵이 30~50타일로 넓어 초안의 3px/틱(180px/s)은 다소 느렸다. 300px/s를 초기값으로 제안하되, 가장 먼저 만져볼 수치다.

속도 조합 예시(기본 300px/s 기준): 탈진 걸린 도망자는 150px/s로 느려져 술래가 순식간에 잡을 수 있고(탈진=킬각), 유체화(+50%)와 탈진(−50%)은 동시에 걸리면 서로 상쇄된다.

## 6. 스킬 시스템

각 플레이어는 **스킬 슬롯 2개**를 가진다.

- **슬롯 1 — Switch**: 도망자에게 자동 부여(고정). 술래가 되면 비활성화.
- **슬롯 2 — 선택 스킬**: 게임 전 `dash / flash / exhaust` 중 **하나**를 골라 장착. 역할(술래/도망자) 무관하게 사용 가능.

즉 **도망자일 때는 [Switch + 선택 스킬]**, **술래일 때는 [선택 스킬]** 만 사용한다.

| 스킬 | 슬롯 | 모티브 | 효과 | 대상 / 조건 | 초기 수치(튜닝 대상) |
|---|---|---|---|---|---|
| **Switch** (술래변경) | 1 (도망자 고정) | 게임 고유 | 다른 생존자 1명을 지목해 **새 술래로 만든다** | 현재 술래와 **근접**(≤240px)해야 발동. 지목 대상은 거리 무관 | 쿨타임 ~7s (실패해도 소모) |
| **dash** (유체화) | 2 (택1) | LoL 유체화 | 자신의 이동속도 **+50%** | 자기 자신 | 지속 10s, 쿨타임 ~20s |
| **flash** (점멸) | 2 (택1) | LoL 점멸 | **즉시 순간이동**(블링크) | 자기 자신 | 블링크 거리 ~640px(2.5타일), 쿨타임 ~15s |
| **exhaust** (탈진) | 2 (택1) | LoL 탈진 | 대상 이동속도 **−50%** | **범위 내 최근접 1명, 진영 무관**(도망자→도망자 가능) | 지속 10s, 사거리 240px, 쿨타임 ~15s |

### Switch 상세

- **발동 조건**: 시전자는 도망자여야 하고, 현재 술래와 중심거리 240px 이내여야 하며, 쿨타임이 아니어야 한다.
- **지목**: 자신과 현재 술래를 제외한 **생존 도망자 중 1명**을 선택. 대상의 위치·거리는 무관하다 — 맵 반대편에서 방심하던 유저에게 술래를 떠넘길 수 있다.
- **결과**:
  - 지목당한 대상 → **새 술래** (광란 +10% / 5s)
  - 기존 술래 → **도망자로 강등** (감속 −10% / 5s)
  - 시전자 → **도망자 유지** (광란 +10% / 5s, 이탈 버스트)
- **실패**(술래와 거리 밖에서 발동)해도 쿨타임은 소모된다.
- **의도**: 추격당하던 유저가 관계없던 제3자에게 술래를 떠넘겨 판을 뒤집는 순간을 만든다. "옆 사람이 갑자기 술래가 되어 혼비백산하는" 장면이 이 스킬의 존재 이유다.

> **미정(TBD)**: 지목당한 대상이 즉시 술래가 될 때, 근처 도망자를 곧바로 잡아버리는 상황을 막기 위한 짧은 무적/유예 프레임이 필요한지. 플레이테스트로 결정.

## 7. 자기장 (맵 수축)

- 게임 시작 후 일정 시간(초안: 10s) 뒤부터, 맵 **사방에서 안쪽으로** 경계가 좁혀 들어온다.
- 자기장 밖으로 밀려난 플레이어는 경계 안으로 강제 이동한다(밖에서 버틸 수 없음).
- 자기장이 지나가면 일부 타일이 제거된다(§8 참고) — 벽이 무너져 새로운 길이 열리고, 사라지는 시야제한 타일이 걷힌다.
- **자기장 진행은 결정론적이다.** 맵 빌드 시 틱 단위 타임라인으로 사전 계산되어 맵 에셋에 포함된다. 따라서 서버는 게임 중 맵/자기장 상태를 스트리밍하지 않는다 — 클라이언트·서버가 게임 시작 시각을 기준으로 동일한 타임라인을 재생한다. (자세한 내용 → `ARCHITECTURE.md` 네트코드 원칙)
- 수축 속도는 맵마다 정의된다(`barrier_speed`, px/틱).

## 8. 맵 & 타일

타일 기반 그리드 맵. `tools/MapBuilder`(Python)로 제작하며, CSV에 타일을 찍고 빌드하면 서버용/클라용 JSON이 나온다. 게임 로직은 타일의 **physics 값**으로 결정된다(텍스처 ID와 별개).

| physics | 의미 | 충돌 | 시야 | 자기장 도달 시 |
|---|---|---|---|---|
| 0 | 바닥 | ✕ | 정상 | — |
| 1 | 벽 | ○ | 막음 | **사라짐**(무너짐) |
| 2 | 수풀(시야제한) | ✕ | 제한 | **유지** |
| 3 | 연막(시야제한) | ✕ | 제한 | **사라짐** |

- **시야 시스템**: 수풀·연막은 시야를 제한한다. 그 안/너머의 플레이어는 보이지 않아 매복·은신이 가능하다. 공정성(안티치트)을 위해 **서버가 각 클라이언트에게 그가 볼 수 있는 것만 전송**하는 것을 원칙으로 한다(→ `ARCHITECTURE.md`).
- **스폰**: 인원수(3~8명)별로 맵 중심을 둘러싼 원형 배치가 맵 빌드 시 사전 계산된다(`start_pos`).
- 현재 제작된 맵: BattleField(50×50), TestMap1(30×30).

> **비고**: `tools/MapBuilder/README.md`의 타일 번호(0~3)는 위 **physics 값**을 가리킨다. `setting.json`의 `num`은 텍스처 ID일 뿐 게임 로직과 무관하니 혼동하지 말 것.

## 9. 강제 술래 교체

- 술래가 일정 시간(초안: 20s) 동안 "성과 없이" 유지되면, 생존 도망자 중 **무작위 1명**이 강제로 새 술래가 된다(광란 +10%/5s 적용).
- 타이머는 **술래가 바뀔 때(수단 불문), 그리고 술래가 도망자를 잡을 때마다 리셋**된다 — 잘 잡고 있는 술래가 억울하게 교체당하지 않도록.
- 목적: 술래가 한 명을 오래 물고 늘어지거나, 아무도 안 잡혀 게임이 늘어지는 상황(캠핑/교착)을 방지.

## 10. 진행 & 스탯

레거시와 달리 계정 시스템이 있어 전적이 영구 저장된다(단 **게스트는 스탯 미저장**, 클라에서 닉네임 색으로 구분 — 아키텍처 참고). `users.stats`(jsonb):

| 필드 | 의미 |
|---|---|
| `level`, `xp` | 레벨 / 경험치 (진행 시스템 — 설계 TBD) |
| `games`, `wins` | 플레이 수 / 최종 생존(승리) 수 |
| `kill` | 도망자를 아웃시킨 총 횟수 |
| `sw_try`, `sw_su` | Switch 시도 / 성공 횟수 |
| `death_order` | 아웃 순서 관련 통계 |

> **미정(TBD)**: 레벨/경험치 획득 공식, 매치 결과 → 스탯 반영 규칙(누가·언제 기록하는지는 `ARCHITECTURE.md`의 매치 결과 처리 참고).

## 12. 상수 요약 (초기값 · `shared`에서 관리)

| 상수 | 초기값 |
|---|---|
| `TILE_SIZE` | 256 px |
| `PLAYER_RADIUS` | 80 px |
| `TAG_DISTANCE` (접촉 판정) | 160 px (중심거리) |
| `TICK_RATE` (시뮬레이션) | 60 Hz |
| `BASE_SPEED` | 300 px/s (5 px/틱) |
| `TAGGER_SPEED_BONUS` | +10% |
| `DASH_BONUS` / `DASH_DURATION` / `DASH_COOLDOWN` | +50% / 10s / 20s |
| `FLASH_DISTANCE` / `FLASH_COOLDOWN` | 640 px / 15s |
| `EXHAUST_SLOW` / `EXHAUST_DURATION` / `EXHAUST_RANGE` / `EXHAUST_COOLDOWN` | −50% / 10s / 240px / 15s |
| `FRENZY_BONUS` / `FRENZY_DURATION` | +10% / 5s |
| `SWITCH_RANGE` / `SWITCH_COOLDOWN` | 240 px / 7s |
| `SWITCH_VICTIM_SLOW` / `SWITCH_VICTIM_DURATION` | −10% / 5s |
| `STORM_START_DELAY` | 10s |
| `FORCED_TAGGER_SWAP` | 20s |
| `MIN_PLAYERS` / `MAX_PLAYERS` | 3 / 8 |

> 모든 값은 튜닝 대상. `SWITCH_RANGE`(240px)는 접촉 판정(160px)과 80px밖에 차이가 안 나 다소 빡빡하니, 숨통을 트려면 ~320px로 넓히는 것을 고려.
