# swITch 독립 기능·품질·보안 검증

진행 중인 기록이다. 종합 점검 완료를 선언하지 않는다. 최초 기준은 `5a986ef058c5fcab9c99f039b244fa43c126bef9`, 작업 브랜치는 `codex/independent-audit-20261004`다. 최초 작업 트리는 깨끗했고 기존 개발 컨테이너와 Azure 데이터는 보존했다.

현재 화면·라우트·컨트롤러·프로토콜·운영 설정에서 먼저 목록을 만들었다. 그 뒤 기존 테스트를 읽고 새로 실행했다. 과거 통과 결과는 이번 증거로 사용하지 않았다. [최초 목록](initial-inventory.md), [UI 도출](ui-inventory.md), [서버 도출](server-inventory.md), [보안/CI 도출](security-inventory.md)에 도출 순서를 남겼다.

## 증거의 수준

- **실제 사용자**: 실제 Chromium 화면과 실제 HTTP/WS, 서버 상태, PostgreSQL 결과를 함께 비교한다. 통합 검사에서 인증·게임·결과 저장을 mock하지 않는다.
- **계층 검사**: DOM/단위/루프백/합성 트랜잭션은 그 범위만 증명한다. 전체 경기 성공과 구분한다.
- **Azure**: 별도 [일회성 결과](azure-results.md)에 기록했다. 게스트3명 2경기, 회원2명+게스트1명 2경기, 새 회원의 저장 전적/권한/리플레이 및 관리자 읽기 화면을 확인했다. 전체 Playwright 실패와 별도 성공 증거를 구분하며 Azure DB 직접 대조는 미실행이다.
- **실패/미실행**: 검사 자체 오류, 제품 결함, 환경 준비 실패를 분리한다. 하위 단계가 실행되지 않으면 `not-run`이다.

## 결함 및 미해결 위험

[확인한 결함·수정·회귀·심각도](defects.md)에 제품 결함과 검사 자체 오류를 분리했다.

### 미해결 위험과 해석

1. 방 이동은 아직 장애에도 원자적인 두 단계 소유권 확정 프로토콜이 아니다. 늦은 채택/프로세스 손실 구간의 소유권 충돌을 완전히 배제하지 못했다. 이번 재현된 시작 경쟁·상태 누락·claim 정리/갱신 결함 수정과 구분한다.
2. Redis 장애 중 메모리 outbox에 쌓인 결과는 게임 프로세스까지 종료되면 영속 보장이 없다. 정상 Redis 재시도 통과가 이를 해결했다는 뜻은 아니다.
3. 의존성 경고의 도달 가능성과 이번 수정은 [의존성 검토](dependencies.md)에 분리했다. 직접 입증되지 않은 인증 우회를 취약점 발견으로 세지 않았다.
4. 사용자 경험 의문(일부 Enter 제출, 가입 코드 만료 뒤 이메일 수정/재발송)은 미확정이다. 현재 동작만을 명세로 삼아 정상 처리하지 않았다.

## 재실행과 CI

[격리 실행 문서](../../deploy/audit/README.md)의 명령은 개발 PC와 GitHub runner가 같다. `AUDIT_RUN_ID`별 DB/Redis/메일/리플레이/증거를 사용하며 기존 자원은 삭제하지 않는다. 빌드 다운로드와 앱 실행의 외부 접속을 분리했다. 앱 실행 네트워크는 internal이고 Azure 자격 증명은 필요 없다.

## 실행 중 발견한 검사 자체의 오류

첫 core 실행의 준비 단계는 합성 설정이 단위 fixture의 빈 ConfigService fallback에 섞이는 문제와 기존 PostgreSQL 통합 assertion의 래핑 오류/생존 XP 누락을 발견했다. 인증 장치를 바꾸지 않고 fixture 환경을 분리하고 실제 SQLSTATE 및 독립 보상식을 검증하도록 바로잡았다.
