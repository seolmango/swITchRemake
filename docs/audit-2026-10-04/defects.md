# 확인한 결함과 남은 위험

P1은 정상 경기·결과·가용성을 크게 해치는 결함, P2는 기능 일부 또는 복구/접근성 결함이다. 이 우선순위는 CVSS가 아니며 모든 항목을 외부 악용 가능한 보안 취약점으로 세지 않는다. 상세 단위 재현은 [서버 기록](server-inventory.md), [UI 기록](ui-inventory.md), [격리 CI 기록](security-ci.md)과 해당 회귀 코드에 있다.

| ID / 우선순위 | 사용자 영향·전제조건 | 확인한 원인·수정 | 회귀 증거 |
|---|---|---|---|
| UI-01 / P1 | 사용자가 Shift+W 같은 이동 키를 저장하면 실제로 이동하지 못함 | 전체 chord를 단일 물리 키로 찾았음. modifier와 본키를 함께 평가하고 구체 설정 우선 | 수정 전 DOM 실패→수정 후 통과. 실제 훈련 서버 위치 변화 통과 |

| S7 / P1 | heartbeat가 오래됐지만 실제 자식이 살아 있으면 최대 worker 수를 넘길 수 있음 | 살아 있는 모든 OS 자식(시작/종료 대기 포함)을 증설 상한에 포함 | max2에서 두 자식 이상이면 hold, 하나이면 정상 증설. Redis 장애 S3와 구분 |

의존성 수정은 [별도 검토](dependencies.md) 참조. scanner의 경고를 새로 재현한 제품 공격으로 세지 않았다. SMTP 설정 변경은 격리 메일 수신함을 위한 확장이며 운영 Gmail 기본값은 유지한다. 테스트용 이메일 sink가 외부 transport verify를 하지 않도록 한 회귀도 포함한다.

## 확인되지 않았거나 해결되지 않은 사항

- **설계 위험:** 방 이동의 양쪽 소유권 확정은 내구성 있는 원자적 프로토콜이 아니다. 늦은 채택/프로세스 손실 구간을 완전히 증명하지 못했다. 정상 이동과 개별 race 수정의 통과가 무손실 이관 전체 보장은 아니다.
- **설계 위험:** Redis 장애 동안 메모리에 보관한 결과 outbox는 게임 프로세스까지 종료되면 유실될 수 있다. 영속 outbox 또는 재처리 원장 설계가 필요하다.
- **재현 못한 의심:** 정상 방 상한100/결과 큐10000/다음 경기 grant 제한 아래에서 동시 종료에 의한 outbox overflow는 재현하지 못했다.
- **의도 확인 필요:** 일부 화면 Enter 제출, 가입 인증 코드 만료 뒤 이메일 수정/재발송 UX. 구현이 존재한다는 이유로 기대 계약을 만족한다고 판단하지 않았다.
- **미실행:** 모든 맵·스킬 조합, 물리 휴대폰·가상 키보드, 실제 OS 공유창·PWA 설치, 패킷 손실/CPU·메모리·디스크 고갈, 장기 retention 및 장애 중 경기 종료의 전구간 무손실 검증. 커버리지 표에서 별도 표시한다.

## 검사 자체 오류

내부 HTTP의 WebCrypto 환경, Docker DNS의 과도한 egress 차단, fixture 환경 변수 혼입, 실제 PostgreSQL 오류 wrapper/생존 XP 기대식, 이름에 번호가 붙는 UI locator, body 없는 요청의 JSON Content-Type, 오래된 세션 토큰, 다중 page의 키보드 focus를 조사했다. 이들 수정은 사용자 기능의 결과·무결성 assertion을 없애기 위한 것이 아니며 제품 결함 수에 포함하지 않는다. 실패 기록은 보존한다.
